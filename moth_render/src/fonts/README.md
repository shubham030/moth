# Fonts

Generated by `tools/fontgen/fontgen.py` and compiled into the firmware. Do not
edit the headers by hand.

## Adding your own font

One command. Any TTF or OTF works — the generator rasterizes it here, so
nothing on the device ever parses a font file:

```
python3 tools/fontgen/fontgen.py MyFont.ttf 28 \
    --name my_font_28 -o moth_render/src/fonts/my_font_28.h
```

That writes the face and rebuilds `registry.h`, which is what the renderer
reads — so the font is live on the next build. Then rebuild and reflash;
fonts are compiled in, so a new one needs new firmware.

Ask for it by size, as usual:

```dart
Text()..value = 'hello'..size = 28
```

`font_for()` returns the largest face at or below the size asked for, so a
28px face answers any request from 28 up to the next face. Bitmap faces are
never scaled up: that blockiness is what these replaced.

**Removing** one is symmetric — delete the header and run
`python3 tools/fontgen/reindex.py`.

Useful flags: `--chars` to subset, `--bpp` (1/2/4/8, default 4) to trade
smoothness for size, `--weight Bold` to pick a named instance of a variable
font.

Whatever you add, its licence is yours to honour — an embedded bitmap is
still a derivative of the original.

Large faces are subsetted, because a full ASCII set at 48px costs 44 KB of
bitmap against 5 KB for digits and a colon. Pass `--chars` with what you
actually draw.

| face | size | characters | bitmap |
| --- | --- | --- | --- |
| `moth_font_14` | 14px | ASCII | 4.1 KB |
| `moth_font_20` | 20px | ASCII | 7.4 KB |
| `moth_font_48` | 48px | digits, colon, space | 5.2 KB |
| `moth_font_72` | 72px | digits, colon, space | 12.0 KB |
